## Validation Runner

Run **only when the user asks**, after an implementation that stayed within a validated plan's scope.

### Why this exists (vs a bare `make test`)
It does not blindly run everything. It (a) selects the **targeted** tests for the zone that actually changed, (b) adds the **cross-zone** integration/contract tests when a boundary is touched, and (c) **justifies** every test it could not run instead of silently skipping.

### Steps
1. **Detect changed zone(s)** — engine / backend / frontend — from the diff (use `detect_changes` from `code-review-graph` if helpful).
2. **Targeted tests for the changed zone:**
   - **Backend:** `cd backend && make test` (lint + phpunit `--group phase1`). For security/contract-touching changes, also run the blocking tests: `tests/Security/TenantIsolationTest.php`, `tests/Security/TenantCacheIsolationTest.php`, `tests/Queue/ConcurrentGenerationTest.php`, `tests/CrossStack/ContractSchemaTest.php`.
   - **Engine:** `cd engine && make test` (pytest + ruff + mypy).
   - **Frontend:** vitest ciblé via `make -C frontend test` — ⚠️ **rebuilder l'image tooling d'abord** (`docker compose --profile tools build frontend-tooling`), elle COPIE le code : sans rebuild on valide une version périmée (piège récurrent). PUIS **les specs e2e listés au plan** (ligne « e2e/Behat impactés » du plan), joués **dans le dépôt principal** via `make -C frontend e2e` avant la PR : la cible exige la stack + `make -C frontend dev`, et son garde bac-à-sable est **fail-closed** (il MEURT en mode play). En mode play, passer par `backend/scripts/with-sandbox.sh` **et annoncer au fondateur avant** (la bascule redémarre la stack). ⚠️ Un spec e2e joué **seul hors wrapper** interroge la base de JEU du fondateur — toujours via le wrapper sandbox.
3. **Cross-zone tests** — when a change touches the backend↔engine contract (Pydantic schemas ⇄ API Platform resources), run `ContractSchemaTest` — it is the guardrail for the manually-synced contract.
4. **Report** — pass/fail per suite, plus an explicit justification for any suite that could not run (stack not up, missing service, etc.).
5. **Behat functional tests — the gate is CI `functional-tests` (required check, CLAUDE.md §4), not a mandatory local run.** Decision fondateur 2026-10-11: Behat no longer runs locally as a matter of course before every PR/merge, because the CI job plays the same suite against the real stack and nothing merges without it green. Run `make -C backend behat` locally (`with-sandbox.sh make -C backend behat` in play mode) only (a) when CI is blocked (e.g. a Docker Hub rate-limit keeps the job from running) or (b) to diagnose a Behat that is red in CI — always under `with-sandbox.sh`. It plays every feature under `backend/features/` against the real stack; the Makefile target has no suite filter (add one only by invoking `vendor/bin/behat --suite=<name>` directly inside the php-fpm container, sandbox-guarded manually). The bash smokes the first 5 replaced are gone (P4-165 — no `.sh` left in `backend/scripts/`); the ones that followed (P4-175 onward) cover the rules that destroy/refuse/isolate, plus the P1-4-adjacent module-matchs features added since (`ls backend/features/` gives the current count, never hardcode it). Diagnostics/warnings in the result are acceptable — the pass criterion is the scenario's own `Alors` assertions (e.g. the CP-SAT solver responded and a plan was produced). ⚠️ `generate-schedule-test.sh` is a *mock* unit test of `generate-schedule.sh` (fake `curl`) — it does NOT exercise the solver; never use it as a functional-test substitute.

### Rules
- **Worktree :** la copie a sa propre stack (`backend/scripts/lib/stack-resolve.sh`). `make -C backend tests-complete` tourne sur un socle de test privé (`test-down` à la fin) ; Behat et e2e sur la stack d'épreuve : `make epreuve-status` → `make epreuve-up WT=<worktree>` → `with-sandbox.sh` → `make epreuve-down` (une seule, partagée : refus si occupée). Jamais de cible destructive sur le principal (détail : `.claude/agents/neo.md` §Worktree).
- Backend and engine tests run **inside Docker** (their Makefiles wrap `docker compose exec`). Ensure the stack is up (`make start`) or report clearly that it is not — do not pretend a skipped suite passed.
- Do not invent test paths. The PHPUnit binary is `vendor/bin/phpunit` (PHPUnit 11), wired into `make phpunit` (which includes `--group phase1`). The suite needs the test DB — run `make db-init-test` first if it is not set up.
- `blocking-tests` must pass before the rest of the PHP suite is meaningful (CI order).
- The Behat feature needs async generation to run: `make -C backend behat` starts/restarts `messenger-worker` itself (a queued message left unconsumed keeps the schedule `PENDING`).
