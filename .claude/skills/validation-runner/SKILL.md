## Validation Runner

Mandatory step of the cycle (`CLAUDE.md` §7 step 5): the orchestrator runs it after an implementation that stayed within a validated plan's scope, before proposing a merge; the rest of the time, only when the founder asks.

### Why this exists (vs a bare `make test`)
It does not blindly run everything. It (a) selects the **targeted** tests for the zone that actually changed, (b) adds the **cross-zone** integration/contract tests when a boundary is touched, and (c) **justifies** every test it could not run instead of silently skipping.

### Steps
1. **Detect changed zone(s)** — engine / backend / frontend — from the diff.
2. **Targeted tests for the changed zone:**
   - **Backend:** `cd backend && make test` (PHPStan + CS-Fixer + PHPUnit testsuite `Unit` seule, `backend/Makefile`). For security/contract-touching changes, also run the tests that guard the touched promise among those of `docs/testing/blocking-tests.md` (the list of what gates; tenant isolation, generation concurrency and the backend⇄engine contracts live there), via `make -C backend phpunit F=<path>`.
   - **Engine:** `cd engine && make test` (ruff, `ruff format --check`, mypy, bandit, deptry, then pytest — `engine/Makefile`).
   - **Frontend:** vitest ciblé via `make -C frontend test` (`lint` rebâtit d'abord l'image tooling, qui COPIE le code ; seule une commande `docker compose … run frontend-tooling` lancée à la main exige `make -C frontend install` avant, sinon elle valide une version périmée). PUIS **les specs e2e listés au plan** (ligne « e2e/Behat impactés » du plan), joués **dans le dépôt principal** via `make -C frontend e2e` avant la PR (UN seul spec : `SPEC=tests/e2e/<nom>.spec.ts`, chemin relatif à `/app/frontend` ; depuis un worktree, sur la stack d'épreuve — variables et plafonds : `docs/testing/testing-strategy.md` § Arguments de la cible `e2e`) : la cible exige la stack + `make -C frontend dev`, et son garde bac-à-sable est **fail-closed** (il MEURT en mode play). `with-sandbox.sh` agit sur la stack de la COPIE d'où il est lancé : depuis le dépôt principal en mode play, il suspend le mode play du fondateur (et redémarre ses workers) le temps de la commande — **annoncer au fondateur avant**, jamais pendant une de ses passes de tests ; depuis un worktree qui occupe la stack d'épreuve, il vise l'épreuve et ne touche pas le fondateur (pas de `backend/.env.local` : exécution directe). ⚠️ Un spec e2e joué **seul hors wrapper** interroge la base de JEU du fondateur — toujours via le wrapper sandbox.
3. **Cross-zone tests** — when a change touches the backend↔engine contract (Pydantic schemas ⇄ API Platform resources), run the three contract tests (`ContractSchemaTest`, `MatchPlacementContractSchemaTest`, `ValidateAssignmentsContractSchemaTest`, `backend/tests/CrossStack/`) — they are the guardrail for the manually-synced contract (`engine/CONTRACT_VERSION`).
4. **Report** — pass/fail per suite, plus an explicit justification for any suite that could not run (stack not up, missing service, etc.).
5. **Behat functional tests — the gate is CI `functional-tests` (required check, CLAUDE.md §4), not a mandatory local run.** Decision fondateur 2026-10-11: Behat no longer runs locally as a matter of course before every PR/merge, because the CI job plays the same suite against the real stack and nothing merges without it green. Run `make -C backend behat` locally (`with-sandbox.sh make -C backend behat` in play mode: from the main checkout it suspends the founder's play mode for the duration — announce it first; from a worktree it targets the epreuve stack) only (a) when CI is blocked (e.g. a Docker Hub rate-limit keeps the job from running), (b) to diagnose a Behat that is red in CI, or (c) as the pre-merge proof of a PR into a lot branch (last paragraph of this step) — always under `with-sandbox.sh`. It plays every feature under `backend/features/` against the real stack; `make -C backend behat SUITE=<name>` plays one suite of `backend/behat.dist.php` only (the `suite` named in the mapping below), same worker restart and sandbox guard. The `.sh` in `backend/scripts/` are tooling (`with-sandbox.sh`, `generate-schedule.sh`…), not functional smokes; the features cover the rules that destroy/refuse/isolate and the matches module (`ls backend/features/` gives the current list, never hardcode a count).    Each feature is self-sufficient (mints its own JWT, creates and cleans its own data, reopens then restores the season-plan pointer where relevant) and runs alone or in any order. All of them run in CI (`functional-tests` job, PR to `main` only), which is the gate — a local run is for the CI-blocked/diagnosis cases above, and for case (c). Diagnostics/warnings in the result are acceptable — the pass criterion is the scenario's own `Alors` assertions (e.g. the CP-SAT solver responded and a plan was produced). ⚠️ `generate-schedule-test.sh` is a *mock* unit test of `generate-schedule.sh` (fake `curl`) — it does NOT exercise the solver; never use it as a functional-test substitute.

   **Case (c) — a PR into `lot/<sujet>`.** Its only CI job is `Lot Gate` (blocking suite, PHPStan, engine and front checks): `backend-tests`, `functional-tests`, `e2e`, Rector, CS-Fixer, Semgrep and `engine-semantics` do not run there (full list: `docs/ops/ci-runner.md` § Branche de lot). Before the merge into the lot: `make -C backend tests-complete` green and, if the diff touches a zone of the table above, its features / e2e specs played on the epreuve stack (`CLAUDE.md` §7 step 5). Behat and e2e then gate at the final PR to `main`; a red found there is bisected across the squashes of the lot.

### Rules
- **Worktree :** la copie a sa propre stack (`backend/scripts/lib/stack-resolve.sh`). `make -C backend tests-complete` tourne sur un socle de test privé (`test-destroy` à la fin du worktree, `test-down` = pause ; `tests-complete` balaie d'abord les stacks orphelines) ; Behat et e2e sur la stack d'épreuve : `make epreuve-status` → `make epreuve-up WT=<worktree>` → `with-sandbox.sh` (vise l'épreuve, jamais la stack du fondateur) → `make epreuve-down` (une seule, partagée : refus si occupée). Dépôt principal : `with-sandbox.sh` suspend le mode play du fondateur, l'annoncer avant. Jamais de cible destructive sur le principal (détail : `.claude/agents/neo.md` §Worktree).
- Backend and engine tests run **inside Docker** (their Makefiles wrap `docker compose exec`). Ensure the stack is up (`make start`) or report clearly that it is not — do not pretend a skipped suite passed.
- Do not invent test paths. The PHPUnit binary is `vendor/bin/phpunit` (PHPUnit 11), wired into `make phpunit` (`--group phase1` when called without `F=`; `F=<path>` runs that file or folder instead). The suite needs the test DB — run `make db-init-test` first if it is not set up.
- The Behat feature needs async generation to run: `make -C backend behat` starts/restarts `messenger-worker` itself (a queued message left unconsumed keeps the schedule `PENDING`).
